# Программа с БД и сервисом для клиентов

Проект демонстрирует проектирование структуры БД, работу с SQL, транзакциями, Django ORM, контейнеризацию и REST API.


## Описание проекта

Реализован backend-сервис для работы с заказами и товарами:

- Категории товаров с неограниченной вложенностью
- Номенклатура товаров
- Клиенты и заказы
- API для добавления товара в заказ с учётом складских остатков
- Защита от конкурентных запросов
- Документация API через Swagger

Технологии:
- Python 3
- Django, Django REST Framework
- PostgreSQL
- Docker, docker-compose
- Poetry
- drf-spectacular (Swagger)

---

## Архитектура данных

### Категории

Категории реализованы через самоссылочную таблицу. Такое решение:

- поддерживает неограниченную глубину вложенности

- соответствует требованиям ТЗ

- используется в ERP и e-commerce системах

Пример структуры:

Бытовая техника
├──1 Холодильники
│   ├──1.1 Однокамерные
│   └──1.2 Двухкамерные
└── 2 Стиральные машины

### Продукт

Продукт принадлежит одной категории.
Характеристики (объём, тип, модель) задаются на уровне продукта.

## SQL (пункты 1 и 2 ТЗ)
Файл sql/schema.sql содержит таблицы (даталогическую схему данных по п. 1 ТЗ):

- category

- product

- lient

- order

- order_item

Категории поддерживают неограниченную вложенность через parent_id.

Файл sql/queries.sql содержит SQL-запросы по п. 2 ТЗ. Предлагается решение по оптимизации: Оптимизация

- Индексы по дате заказа и внешним ключам

- Денормализация root_category_id

- Материализованное представление

- Партиционирование таблицы order по дате


## Установка сервиса по п. 3 ТЗ:

1. Клонируйте репозиторий:

```
git clone -b develop https://github.com/Rapunzel-Chan/clientshop.git
```

2. Установите зависимости:

```
pip install -r requirements.txt
```

## Использование:

1. Переключитесь на проект:

```
cd BD_clients
```

2. Создайте виртуальное окружение:

```
python -m venv venv
```

3. Активируйте виртуальное окружение:

- Windows:

```
.\venv\Scripts\activate
```

- Linux/macOS:

```
source venv/bin/activate
```

4. Создайте .env файл в корне проекта и заполните данные на примере .env.example.

5. Откройте POSTMAN и проверьте работу REST API :

(эндпоинт)
```
POST /api/add-product/
```
(тело запроса)
```
{
  "order_id": 1,
  "product_id": 2,
  "quantity": 3
}
```
Поведение:

- Если товара нет в наличии → ошибка 400

- Если товар уже есть в заказе → увеличивается количество

- Остатки товара уменьшаются

Транзакции и защита от гонок

Для защиты от одновременных запросов используется:

- transaction.atomic()

- select_for_update() при работе с остатками товара
```
with transaction.atomic():
    product = Product.objects.select_for_update().get(id=product_id)
```

Это гарантирует корректную работу при параллельных запросах.

## Запуск и проверка сервисов приложения в Docker-контейнере

1. Установите Docker и Docker Compose.
2. Убедитесь, что в корне проекта есть: `Dockerfile`, `docker-compose.yml`, `.env.example`
3. Создайте .env и заполните необходимые значения
4. Запустите всю систему:
```
docker compose up -d --build
```

5. Выполните миграции для полноценной работы :

```
docker-compose run --rm backend python manage.py migrate
```

6. Проверка работы контейнеров:

```
docker-compose ps
```
